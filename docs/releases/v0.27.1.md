# SecondBox v0.27.1

## Deployment boundary

Deployments from v0.14.0 onward update in place and retain their Sandboxes,
Workspaces, Profiles, and authorities. There is no database migration, public
API v1 is unchanged, the Runner protocol stays at generation 7, and the
Firecracker bundles, gVisor materialization inputs, and standard Profile
revisions are unchanged, so v0.27.0 and v0.27.1 peers connect in either update
order. Both fixes are in the Runner; update the Runners to receive them.

When upgrading from an earlier release, also follow the
[v0.27.0 notes](v0.27.0.md) and the intervening release notes.

## Workspace storage

Stopping or fencing a Sandbox now releases the host blocks behind files its
guest deleted. Before, freed ext4 blocks stayed allocated in the Workspace
image on both Firecracker and gVisor, so `allocatedBytes` never fell after
files were deleted, and storage meters built on `exclusiveBytes` kept
charging them.

- The Runner reclaims when it advances a stopped Workspace's generation, under
  the Workspace writer lock, by reading the image's ext4 block bitmaps and
  punching holes over free runs that are at least 1 MiB after inward
  alignment to 64 KiB. No guest, VMM, or protocol change is involved.
- Punching drops only the Workspace image's reference. Blocks still shared
  with a Snapshot or the capacity template stay held by that holder and are
  not copied, so reclaiming them lowers `allocatedBytes` but not
  `exclusiveBytes`. Where `exclusiveBytes` is measured, it falls by the
  reclaimed unshared extents in the next storage observation.
- The pass punches nothing when the filesystem was not cleanly quiesced, records
  filesystem errors, uses an unsupported feature, or fails a checksum or free-count check, and it
  skips a relocation-sealed Workspace. Firecracker stops freeze the guest
  filesystem instead of unmounting it, so a guest that removed its ext4
  journal never reclaims on Firecracker.
- One pass punches at most 4,096 ranges and the next stop or fence resumes.
  `ENOSPC` and `EDQUOT` end the pass; other punch errors fail the generation
  advance.
- The pass runs synchronously on the stop path, so a stop can take longer,
  depending on image size, fragmentation, and host storage. Each completed
  pass logs `SecondBox WorkspaceStore freed-block reclaim` with its outcome,
  the allocation before and after, and `elapsedMs`; a failed pass surfaces
  through the generation-advance error instead.
- Existing Workspaces reclaim at their next stop or fence. A Workspace that
  stays stopped is not swept.
- Punched ranges are ordinary sparse holes with no manifest or format change,
  so a v0.27.0 Runner reads a reclaimed Workspace unchanged.

## Runner networking

A restarted Firecracker Runner moves its host `INPUT` and `FORWARD` jumps back
above Docker's. Before, a Docker daemon restart re-inserted Docker's jumps
above the surviving Runner jumps, and on a same-host Runner whose gateway is on
an internal Docker network, Docker's isolation rule then dropped all guest
egress to the gateway until the jumps were moved by hand. With Docker
`live-restore`, restart the Runner container after a daemon restart.

## Switching backends

The gVisor runtime guide's "Switching an installation between Firecracker
and gVisor" now stops every Sandbox of the pool through the lifecycle API and
waits for its Operation before the Runners stop. A Runner that stops first
disconnects before it ends its Instances, and an Instance it leaves running
stays fencing until the same Runner reconnects on its old backend.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes
Linux amd64 OCI images, and the arm64 artifact set publishes the
control-plane, Runner, installer-tools, and microVM-artifact images for Linux
arm64. CLI and deployment binaries ship for Linux and macOS on amd64 and
arm64. It includes the Btrfs-image installer qualification; it does not
include gVisor pod qualification.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.27.1`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.27.1`.
