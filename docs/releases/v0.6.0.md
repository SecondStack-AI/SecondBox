# SecondBox v0.6.0

SecondBox v0.6.0 adds customer-shared tenancy: one customer-operated deployment
can serve multiple SecondStack installations in the same trust domain through
persisted delegated authorities, atomic two-level quotas, and durable Subject
cleanup.

This is a clean-install boundary. A v0.5.2 manifest or deployment containing the
retired static application-authority surface is refused with a clean-reinstall
diagnostic. There is no import, compatibility, fallback, or dual-source mode.

## Delegated management and isolation

- The platform token creates Tenants and tenant-controller authorities and
  retains Profile, RunnerPool, Runner, deployment-usage, and aggregate-timing
  administration.
- A tenant controller is fixed to one Tenant and manages only its Subjects,
  application authorities, and Tenant usage. It cannot call Sandbox routes.
- An application authority is fixed to one Tenant, one Subject, exact Sandbox
  scopes, and explicit Profile grants. It cannot call management, Profile
  mutation, Runner administration, deployment usage, or aggregate timing.
- PostgreSQL stores only public credential lookup identifiers and one-way
  verifiers. Bearer material is returned once after successful creation or
  rotation, and revocation or expiry applies on the next request.
- Tenant aggregate and Subject quota are reserved and released in one
  transaction for Sandboxes, Instances, vCPU, memory, Snapshots, Port sessions,
  and concurrent operations. Tenant quota also bounds active Subjects and
  application authorities.

Subject closure immediately revokes application admission. An explicit cleanup
request creates one restart-safe cleanup Operation; Subject expiry creates the
same durable operation automatically. Both paths cancel work, delete Snapshots
and Sandboxes, release Leases and quota, and obtain Runner acknowledgement for
Workspace removal.

## Standard resources and networking

The release adds the explicitly selected `agent-compartment-isolated` standard
bundle. It retains bounded command, File, Workspace, cancellation, and lifecycle
capabilities while denying outbound network, DNS, and Ports. Existing
`agent-compartment` and `durable-coding` lineages remain ordinary immutable
release-owned resources.

Network-enabled RunnerPools still map to one trusted egress context. A logical
gateway mapping authorizes a destination but does not provide guest DNS. The
Runner DNS proxy forwards to its upstream and rejects protected-address answers;
production deployments qualify their own logical gateway resolution,
authentication, and reachability.

## Installation and upgrade

Install from the stable release bootstrap, or verify and invoke the staged
`secondbox-deploy` binary directly. Production initialization creates only the
platform authority. After readiness, use the typed CLI management sequence to
create a Tenant, controller, Subject, and application authority.

```sh
curl -fsSL https://github.com/SecondStack-AI/SecondBox/releases/latest/download/install.sh | sh
npm install @secondstack-ai/secondbox@0.6.0
go get github.com/SecondStack-AI/SecondBox@v0.6.0
```
