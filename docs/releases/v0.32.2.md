# SecondBox v0.32.2

v0.32.2 has the same code as [v0.32.1](v0.32.1.md) and restores the Linux arm64
runtime artifact set that v0.32.1 omitted. Follow the
[v0.32.1 deployment boundary](v0.32.1.md#deployment-boundary) when updating.
A deployment already on v0.32.1 needs no update.

The v0.32.0 arm64 stage failed only in scenario qualification, because the
arm64 release runner selected an execution image from an unreachable registry.
That runner now uses the public GHCR selected-image fixture, as the amd64
runner does, and the tag workflow again qualifies and stages both sets.

## Distribution

The default release qualifies Firecracker, local gVisor and the Btrfs-image
installer. It publishes Linux amd64 images for the control plane, Runner,
installer tools, microVM artifacts, gVisor Runner and gVisor artifacts. The
arm64 set publishes the control plane, Runner, installer tools and microVM
artifacts. gVisor pod qualification is outside the default release tier.

CLI, deploy, fleet-controller and fleet-enrollment binaries ship for Linux and
macOS on amd64 and arm64. The guided installer still installs only the CLI and
deploy tool. Fleet tools are installed separately by their operator.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.32.2`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.32.2`.

## Bundle identity

Firecracker execution bundles are retained from v0.31.0. The amd64
`secondbox-0.31.0` bundle manifest remains
`sha256:d7e570672f872781798f96f4026f1f068254ede3604bd0f9bc540111aab084cc`;
the arm64 bundle remains the one described by the v0.31.0 artifact manifest.
See the [v0.31.0 bundle notes](v0.31.0.md#bundle-identity) for component identities
and the architecture-specific trust-store boundary.

Use the new release's verified artifact manifest for container, binary and
gVisor materialization digests.
