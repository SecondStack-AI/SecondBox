# SecondBox v0.32.5

## Deployment boundary

This release adds renewable archive credentials for non-AWS control hosts and
the optional pre-baked AWS worker AMI workflow. It replaces the unpublished
v0.32.3 and v0.32.4 tags. Public API v1, Runner protocol
generation 8, database migrations and standard Profile revisions are unchanged
from v0.32.2. Existing v0.32.1/v0.32.2 deployments update in place. Keep the control
plane, all Runners, fleet controller and enrollment tools on the same build.
No existing fleet is switched to an AMI automatically.
The guided updater's supported source floor remains v0.14.0.

The worker bundle command now requires the checksum-verified Linux amd64
enrollment binary from the selected release between the enrollment CA and output
directory arguments. Use the invocation in the
[AWS fleet reference](https://github.com/SecondStack-AI/SecondBox/blob/v0.32.5/deploy/aws-fleet/README.md); the builder no longer
compiles an enrollment client with a development identity.

Upgrades from v0.31.x or earlier must follow the complete
[v0.32.1 coordinated cutover procedure](https://github.com/SecondStack-AI/SecondBox/blob/v0.32.5/docs/releases/v0.32.1.md#deployment-boundary).
Settle cloud/volume and archive object cleanup before recovery capture, then
verify enrollment and a start on each served Profile before reopening service
and resuming policies.

## Renewable archive credentials

A non-AWS control host can set
`deployment.workspace_archive_aws_config_directory` to a private directory
containing the AWS shared `config` and its credential-provider inputs. The
deployment mounts it read-only at `/run/secondbox-archive-aws` in the control
plane only. This binding sets `AWS_CONFIG_FILE` and disables IMDS; workers
receive only the existing expiring transfer grants.

Use a separately scoped archive-signing role and renewable `credential_process`,
such as IAM Roles Anywhere. The configured file must be readable by the actual
control-plane identity at startup. Provider executables and certificate/key paths
must resolve inside the mount; keep CA signing keys outside it. The fleet
controller has its own AWS role and credential configuration.

Archive signing attempts one early refresh per signing request when the cached
session has fewer than 90 seconds remaining. Grants still expire at least 30 seconds before the AWS session and
require at least one minute of validity. This does not replace certificate
rotation, IAM trust, permission scoping or a site's private-network setup.
See [storage tiering](https://github.com/SecondStack-AI/SecondBox/blob/v0.32.5/docs/operations/workspace-storage-tiering.md)
for the supported binding and recovery behavior.

## Execution-image download diagnostics

Failed image preparation retains the final Skopeo error after long layer-copy
progress, within the existing bounded diagnostic output. Transfer, extraction,
admission and timeout limits are unchanged. This diagnostic change does not
assert a cause or fix for v0.32.4's failed selected-image qualification.

## AWS worker bundle credentials and cache integrity

The v0.32.1/v0.32.2 bundle builder copied the whole optional Runner execution
cache, including transient registry authentication files left during image
preparation or after an interrupted process. The builder now exports only the
fixed execution-bundle files from complete digest directories and verifies
their checksums, excluding authentication, operation and retention records.

Operators who packaged a mutable Runner cache should inspect their existing
bundle contents and revoke any registry credentials included there before
continuing to distribute that bundle. Rebuild from a quiesced cache or offline
copy with the updated builder.

Worker bootstrap verifies private staging before atomically publishing a
complete digest directory under the Runner lock. Interrupted staging can be
retried without retaining partial published image bytes or replacing live cache
locks.

## Pre-baked worker AMIs

The reference builds an identity-free AMI from an explicitly pinned worker
bundle. Runtime images are preloaded; execution-image data stays compressed
until it is staged sparsely onto each worker's fresh XFS disk. Every worker
enrolls independently and receives its own credentials. AMIs contain no enrolled
worker identity or workspace data.

AMI construction requires a single EBS root at `/dev/sda1`. Base images declaring
additional disks, including ephemeral mappings, must be replaced with an explicit
single-root base. The provisioner observes a fresh nonce on the running builder's
serial console after identity scrubbing, requests an EC2 stop, then verifies
stopped state and root-only topology before imaging. The guest powers off after
five minutes if the provisioner disappears. The provisioning role requires
`ec2:GetConsoleOutput` and `ec2:StopInstances` for owned builders, alongside its
existing scoped construction permissions; worker roles do not need them.

An unrelated stop or a stale nonce is insufficient. Catchable SIGTERM uses the
bounded, receipted cleanup path, including when it first arrives during cleanup.
After SIGKILL or host loss, inspect the receipt and owned AWS inventory before
retrying. Failed image and snapshot outputs remain for explicit inspection and
cleanup.

Select pre-baked mode explicitly and keep the AMI, bundle location and both SHA
inputs consistent. An absent or mismatched cache fails explicitly. Pre-baking
has not demonstrated a cold-start latency improvement; initialization of cold
EBS snapshot blocks remains a workload-specific consideration.

The sealing handoff was exercised on real EC2 using published v0.32.1 runtime
inputs. Earlier Code build/archive/zero-worker/restore evidence also used that
runtime. Qualify the selected release's actual AMI, private connectivity and
Code workload on the intended deployment before enabling a permanent pool.

See [AWS workers](https://github.com/SecondStack-AI/SecondBox/blob/v0.32.5/deploy/aws-fleet/README.md) for bundle construction,
provisioner/controller permissions, cache requirements and safe retirement.

## Distribution and bundle identity

Both amd64 and arm64 runtime artifact sets are retained. The gVisor images and
artifacts remain amd64-only, as does the AWS worker reference. CLI, deploy, fleet-controller and fleet-enrollment
binaries ship for Linux/macOS on amd64/arm64; fleet tools are installed separately
by their operator.

The Firecracker bundles remain those documented by v0.32.2/v0.31.0. Use this
release's published artifact manifests and checksums for all binary, container
and gVisor materialization identities. SDK coordinates are
`@secondstack-ai/secondbox@0.32.5` and
`github.com/SecondStack-AI/SecondBox@v0.32.5`.
