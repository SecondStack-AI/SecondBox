# SecondBox v0.11.0

SecondBox v0.11.0 gives everyday Sandbox use one command per intent and gives the
project one-command qualification and release. It was published without release
notes; these were written after publication from the release commit and
[#126](https://github.com/SecondStack-AI/SecondBox/pull/126),
[#130](https://github.com/SecondStack-AI/SecondBox/pull/130), and
[#131](https://github.com/SecondStack-AI/SecondBox/pull/131).

## Sandbox commands

`create`, `start`, `stop`, `rm`, `ls`, `get`, `cp`, `ls-files`, `ports forward`,
`snapshot`, `snapshots`, `restore`, and `snapshot rm` replace hand-written HTTP
aliases. `run` and `create` accept `--size small|medium|large` presets or explicit
`--cpus`, `--memory`, and `--disk` requests bounded by optional Profile ceilings,
quota, and Runner admission, and `--from sandbox/snapshot-name` starts from a
golden Snapshot. Ready Snapshot names are unique per Sandbox (migration `0024`), so
`mybox/with-deps` is a stable reference. Guided installation records a
`tenancy_bootstrap` stage and its smoke stage runs a command in isolated and
durable-coding microVMs.

```sh
secondbox run durable-coding --size large --name mybox --keep -- true
secondbox snapshot mybox --name with-deps
secondbox run durable-coding --from mybox/with-deps -- npm test
```

## Deployment settings

Deployment manifests drop seven unused Subject quota defaults and the unenforced
RunnerPool `capacityPolicy` (API, SDKs, resource documents, CLI `--capacity`, and
pool fields `max_sandboxes`, `max_vcpu_count`, `max_memory_bytes`); a forward
migration drops its column. Packaged listeners, catalog location, same-host Runner
paths, and the jail policy are derived. Polling intervals move to optional
`[overrides]`. Retired fields are rejected; follow the field removals in the
deployment guide.

## Upgrade

Migration `0024` requires that no Sandbox holds duplicate ready Snapshot names. On
the source release, list Snapshots per Sandbox and delete unwanted duplicates by
identifier before updating; duplicates block control-plane startup.

The Firecracker bundle and trust anchor are unchanged from v0.6.0. The guest-side
port-credit fixes merged for this release ([#127](https://github.com/SecondStack-AI/SecondBox/pull/127),
[#128](https://github.com/SecondStack-AI/SecondBox/pull/128),
[#129](https://github.com/SecondStack-AI/SecondBox/pull/129)) therefore reach
Firecracker guests only with the rotated v0.12.0 bundle; gVisor guests receive them
in this release.

```sh
npm install @secondstack-ai/secondbox@0.11.0
go get github.com/SecondStack-AI/SecondBox@v0.11.0
```

## Release tooling

`just qualify` runs the ten gates and a sharded Firecracker suite; `just release
VERSION` qualifies, builds, binds commit-exact evidence, runs installer guests,
and stages a release with per-stage logs and timings. This was the first release
cut with it.
