# SecondBox v0.5.1

SecondBox v0.5.1 fixes interactive CLI sessions that could forward terminal capability replies into a Sandbox shell as unintended input. It also preserves the canonical spawn-failure reason in Go SDK Exec failures.

This is a compatible patch release for v0.5.0. The public HTTP contract, Runner protocol, guest protocol, database schema, deployment manifest, standard resources, and signed microVM bundle are unchanged.

## Interactive shell input remains clean

The styled CLI activity indicator previously used a terminal UI runtime that queried terminal capabilities and enabled keyboard and paste modes even though the indicator did not consume standard input. Terminal emulators answered those queries on standard input. An interactive `secondbox shell` session could then forward the unread replies byte-for-byte to the guest, where `/bin/sh` interpreted semicolon-delimited fragments as commands.

The activity indicator is now a one-way renderer. It never reads standard input, emits no terminal capability queries or keyboard-mode controls, and limits its output to cursor positioning and bounded status text. Its output remains within the terminal width when a terminal is narrow or resized, and real-pseudoterminal regression tests verify that prohibited query and mode sequences are absent.

Plain output remains non-animated. A terminal session that was already open with an older CLI may still contain replies queued before upgrading; close that session before starting a new shell with v0.5.1.

## Exec spawn failures retain their reason

The Go SDK's `ExecFailure` now carries the canonical `SpawnFailureReason` returned by the service, such as `not_found`. Its error string includes that reason, so callers and CLI diagnostics can distinguish why the guest could not spawn a command without parsing a generic message.

## Upgrade

Upgrade the CLI and SDK clients that initiate interactive sessions. Existing v0.5.0 control-plane and Runner deployments remain protocol-compatible, but coordinated deployments should use the v0.5.1 images and release assets.

```sh
curl -fsSL https://github.com/SecondStack-AI/SecondBox/releases/latest/download/install.sh | sh
npm install @secondstack-ai/secondbox@0.5.1
go get github.com/SecondStack-AI/SecondBox@v0.5.1
```
