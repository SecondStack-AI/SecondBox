# SecondBox v0.20.0

## Deployment boundary

This release keeps Runner protocol generation 5 and public API v1, adds migrations `0032_port_stream_accounting` and `0033_port_stream_in_memory` to the v0.15.0 baseline, and ships no new execution bundle or standard Profile revision. Deployments from v0.14.0 onward update in place and keep their Sandboxes, Workspaces and authorities. Update the control plane and all Runners together; a mixed pairing is not qualified, and an older Runner keeps the Port and Terminal frame-ordering faults this release fixes.

Both migrations drop retired `port_sessions` columns that the v0.19.0 control plane still reads. Rolling back after the update therefore requires the pre-update database backup, not only the previous binaries.

Exec, Terminal, file, directory and Port session requests now enforce the application authority's `profileGrants` (see [Security](#security)); an authority that reached a Sandbox on an ungranted Profile receives `authorization_failed` after the update. The routes that add a grant in place first ship in this release, so sequence the update:

1. Before updating, compare each application authority's `profileGrants` with the Profiles of the Sandboxes in its Subject, and list the gaps.
2. Pause the application traffic that depends on a missing grant.
3. Update the control plane and all Runners.
4. Add each missing grant with `extendTenantCeiling` where the Tenant ceiling lacks it, then `extendApplicationAuthority`, described under [Authorities](#authorities). The authority keeps its credential.
5. Resume the paused traffic.

## Security

Application data-plane requests (exec, terminals, files, directories and Port sessions) require the addressed Sandbox's Profile to be in the authority's `profileGrants`. Previously grants gated only Profile reads and Sandbox creation, so an application could exec into a Sandbox that the platform or another authority had created in its Subject on a Profile it was never granted. Reads, listing, Leases and lifecycle remain Subject-scoped.

## Authorities

`POST /v1/tenants/{tenantRef}:extend-ceiling` (`extendTenantCeiling`) and `POST /v1/application-authorities/{authorityId}:extend` (`extendApplicationAuthority`) add Profile grants or application scopes to an existing Tenant ceiling or application authority without re-creating it or rotating its credential. Both are add-only, revision-fenced and idempotent, and an authority extension must stay within its Tenant ceiling. The CLI exposes them as `secondbox tenant extend-ceiling` and `secondbox application-authority extend`, and both SDKs add the operations. See [Extending grants](../design/profiles-and-authorization.md#extending-grants).

## Port sessions

- Proxied Port traffic no longer touches PostgreSQL while it streams. Payload, credit and sequence state live in memory; PostgreSQL records only a session's admission, consumption, close and terminal outcome, and the close stamps `lastActivityAt`. Data-plane traffic, including a direct Port connection, no longer changes the Sandbox `revision`, which previously advanced once or twice per chunk and starved lifecycle reconciliation with revision conflicts.
- Port sessions have no per-session byte limit. Proxied sessions were capped at the smaller of `execution.maximumTransferBytes` and `SECONDBOX_DATA_PLANE_MAXIMUM_SESSION_BYTES`, which ended a live browser view after about 12 minutes. Both limits still apply to Exec and File sessions.
- A PortSession lives while the Lease it was admitted under is renewed, bounded by its `durationSeconds` and the Port policy's `maximumSessionSeconds`, instead of ending at the Lease's first expiry. The Go SDK's `ForwardPort` and `secondbox ports forward` request the policy's full duration for each connection.
- A proxied client that writes ahead of the Runner's credit waits for the credit frame instead of sleeping one 250 ms data-plane poll interval.
- The Firecracker and gVisor relay applies credit backpressure to the guest within a fixed 256 KiB receive window instead of disconnecting fast streams after 16 queued frames.
- A PortSession whose tunnel closed while the Runner waited for credit no longer stays `cancelling` and counts toward `concurrentOperations`. Existing stuck sessions converge at the first data-plane sweep after the update.

## Runner reliability

A Runner could send Port frames, or a Terminal output frame through an attachment that had just been detached, out of sequence order. The control plane then dropped the Runner's whole connection and every data-plane session on it. Both paths now send in sequence order.

## Request validation

`invalid_request` problems name each refused input in `details`: the JSON path in the request body, with array elements as `[index]` (`spec.ports[1].maximumSessions`); a header by its canonical name (`If-Match`); or a path or query parameter (`limit`). A problem with exactly one detail uses it as its `title`, so SDK and CLI error messages show it; others keep `Request is invalid`. Profile resource-alignment details now use the request path (`spec.resources.memoryBytes`) instead of `resources.memoryBytes`. See the [API conventions](../design/api-conventions.md).

## Client execution images

The client execution image builder requires `SECONDBOX_CLIENT_IMAGE_BROWSER_POLICY` (`forbid` or `allow`). Set `forbid` to keep the previous behavior; `allow` lets an application ship a headless browser in its own signed userspace and records `browserPolicy: allow` in the signed rootfs contract. See the [microVM image pipeline](../operations/microvm-image-pipeline.md).

## Firecracker bundle and trust anchor

The release retains the signed `secondbox-0.17.0` Firecracker bundle and the v0.12.0 RSA trust anchor. Standard Profile revisions and their spec digests are unchanged from v0.19.0.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes Linux amd64 OCI images. CLI and deployment binaries ship for Linux and macOS on amd64 and arm64. The public API remains v1 and the Runner protocol window remains `[5,5]`.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.20.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.20.0`.
