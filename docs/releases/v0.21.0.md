# SecondBox v0.21.0

## Deployment boundary

This release advances the Runner protocol to generation 6 exactly, keeps public API v1 with a breaking change to attributed execution, adds migration `0034_per_exec_attribution` to the v0.15.0 baseline, and ships no new execution bundle or standard Profile revision. Deployments from v0.14.0 onward update in place and keep their Sandboxes, Workspaces and authorities.

Update the control plane and all Runners together. Generation 5 and generation 6 peers refuse each other, so a Runner that is not updated cannot reconnect, and its Sandboxes are unavailable until it is.

Migration `0034_per_exec_attribution` drops the attributed-execution columns from `assignments` and adds the binding to `data_plane_sessions`. It is forward-only: rolling back after the update requires the pre-update database backup, not only the previous binaries.

Attribution moves from the start request to the exec request, and a Runner must route the attributed gateway for every Sandbox of a permitting Profile. Sequence the update:

1. On every Runner that hosts Sandboxes of a Profile with `attributedExecution`, such as the standard `agent-compartment`, configure `attributed_socket` for that Profile's gateway in each pinned egress context, and deploy the attribution-aware gateway beside it. v0.20.0 Runners already accept the setting. After the update, an Assignment of such a Profile fails without the route, so those Sandboxes no longer start.
2. Take the database backup.
3. Pause attributed traffic and let in-flight attributed starts and their commands finish. Earlier clients send `attributedExecution` on start, which this release rejects as `invalid_request`; clients built on this release send it on exec, which earlier control planes reject.
4. Update the control plane and all Runners.
5. Deploy clients built on the v0.21.0 SDKs, then resume attributed traffic.

## Attributed execution

- `StartSandboxRequest.attributedExecution` is removed. `BufferedExecRequest` and `StreamingExecRequest` accept `attributedExecution {authorizationRef, expiresAt}`. Start the Sandbox normally and attribute the exec that needs credentials; stopping the Sandbox before a credentialed command is no longer needed.
- An attributed exec runs in the Sandbox's ordinary generation with its ordinary network policy, Runner gateways, terminals, Ports and file writes. The Instance is not stopped or fenced afterwards, and one generation admits any number of sequential or concurrent attributed execs.
- Admission requires the `sandbox:exec` scope and Profile grant, Profile permission, a pinned Tenant egress context, an `expiresAt` within the Profile execution deadline that the exec deadline does not outlive, and a home Runner that advertises `per-exec-attribution`; otherwise it returns `503 home_runner_unavailable`. The binding is stored with the exec session and covered by its idempotency key. Attributed exec streams use the proxied transport, and terminals cannot be attributed.
- Each attributed exec gets its own Runner listener on the Instance interface, added to the Instance firewall policy for that exec only, and `SECONDBOX_EXECUTION_GATEWAY` is injected into that exec alone. The listener and its relays close when the exec ends, is cancelled, reaches its deadline or `expiresAt`, or loses its control-plane connection. The `SBXATTR1` identity preface is unchanged, so gateways need no change.
- While a window is open, any process in the Instance can reach its listener under that exec's identity. This is an accepted residual risk: the sandbox never holds real credentials, and the application's gateway and Integrations authorize each credentialed request. See the [threat model](../design/threat-model.md).
- The Go and TypeScript SDKs follow the new request shape. See [attributed commands](../operations/sdk-cli-and-flue.md#attributed-commands).

## Runner protocol

Generation 6 moves attribution from `AssignmentCommand` to `ExecOpen.attributed_execution`, adds `AssignmentCommand.attributed_execution_permission` (the pinned gateway and resolved per-exec connection limit) to every Assignment of a permitting Profile, and replaces the `attributed-execution` capability with `per-exec-attribution`. Firecracker and gVisor Runners advertise it when attributed routing is configured. See the [Runner protocol](../design/runner-protocol.md).

## Firecracker bundle and trust anchor

The release retains the signed `secondbox-0.17.0` Firecracker bundle and the v0.12.0 RSA trust anchor. Standard Profile revisions and their spec digests are unchanged from v0.19.0.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes Linux amd64 OCI images. CLI and deployment binaries ship for Linux and macOS on amd64 and arm64. The public API remains v1 and the Runner protocol window is `[6,6]`.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.21.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.21.0`.
