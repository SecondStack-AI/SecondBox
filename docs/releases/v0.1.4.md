# SecondBox v0.1.4

SecondBox v0.1.4 is the first stable public release of the self-hosted control plane for durable, hardware-isolated development sandboxes.

## Highlights

- Run untrusted workloads in Firecracker microVMs while preserving each Sandbox's workspace across stops, restarts, and compute generations.
- Operate an unprivileged control plane with PostgreSQL and S3-compatible Artifact storage, connected to separately deployed privileged Runners.
- Use real streaming Exec, filesystem access, reconnectable PTYs, scoped ports, local reflink Snapshots, Leases, immutable Artifacts, and explicit stopped-Sandbox relocation.
- Manage Sandboxes through the `secondbox` CLI or equivalent Go and TypeScript lifecycle clients, including Node transports and a Flue 2 adapter.
- Deploy from a strict `secondbox.toml` manifest with `secondbox-deploy`, explicit RunnerPools, and the release-owned `agent-compartment` and `durable-coding` Profiles.

## Install

Download `secondbox` and `secondbox-deploy` for your OS and architecture from the assets below. For Linux amd64:

```sh
mkdir -p ~/.local/bin
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.1.4/secondbox_0.1.4_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.1.4/secondbox-deploy_0.1.4_linux_amd64
install -m 0755 secondbox_0.1.4_linux_amd64 ~/.local/bin/secondbox
install -m 0755 secondbox-deploy_0.1.4_linux_amd64 ~/.local/bin/secondbox-deploy
```

Install an SDK at the same version:

```sh
npm install @secondstack-ai/secondbox@0.1.4
go get github.com/SecondStack-AI/SecondBox@v0.1.4
```

## Fixes included in this release

- Generated RunnerPools include the mandatory `compute` capability, so the standard Profiles can be admitted.
- RunnerPool architectures and capabilities are compared as sets, avoiding false drift when their order changes.
- Deployment lifecycle clients tolerate Runner enrollment races, refresh state between transitions, and wait until a Sandbox is stopped.
- Runtime and toolchain component identities remain distinct in the artifact manifest and standard resource bundles.
- The packaged Go SDK check resolves the correct `sdk/go/secondboxclient` package.

## Runtime requirements

Executing Sandboxes requires a Linux amd64 Runner host with KVM and TUN, cgroup v2, and a dedicated XFS or Btrfs workspace filesystem with reflink support. The control plane can run separately; only the Runner needs access to these host facilities.
