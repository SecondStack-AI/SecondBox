# SecondBox v0.2.1

SecondBox v0.2.1 is a patch release that stops the same-host runner deployment from leaking bind mounts into the host mount namespace.

## The fix

The same-host runner Compose service bound its state and workspace directories with `rshared` propagation. When `workspace_root` nested inside the state mount — which the jail staging hard-link requirement pushes same-host deployments toward — every runner container start propagated the workspace bind back into the host mount namespace, doubling a stack of byte-identical mounts on the workspace host directory (2^n − 1 growth, with a mirror stack inside the state host directory). The leaked mounts survived container teardown, made the workspace directory undeletable, blocked re-bootstrap, and grew the host mount table without bound.

Both binds now use `rslave`. The runner creates no mounts intended for the host, so host-to-container propagation is preserved and the leaking direction is cut.

## Recovering an affected host

Hosts that ran a v0.2.0 same-host runner with a nested `workspace_root` may still hold the leaked mounts; upgrading does not remove them. With the deployment down, unmount both stacks — the workspace host directory and the mirror path inside the state host directory named after the final `workspace_root` segment:

```sh
for p in "$WORKSPACE_HOST_DIR" "$STATE_HOST_DIR/$(basename "$WORKSPACE_ROOT")"; do
  while mountpoint -q "$p"; do umount "$p" || break; done
done
```

## Install

Download `secondbox` and `secondbox-deploy` for your OS and architecture from the assets below. For Linux amd64:

```sh
mkdir -p ~/.local/bin
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.1/secondbox_0.2.1_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.1/secondbox-deploy_0.2.1_linux_amd64
install -m 0755 secondbox_0.2.1_linux_amd64 ~/.local/bin/secondbox
install -m 0755 secondbox-deploy_0.2.1_linux_amd64 ~/.local/bin/secondbox-deploy
```

Install an SDK at the same version:

```sh
npm install @secondstack-ai/secondbox@0.2.1
go get github.com/SecondStack-AI/SecondBox@v0.2.1
```

## Runtime requirements

Executing Sandboxes requires a Linux amd64 Runner host with KVM and TUN, cgroup v2, and a dedicated XFS or Btrfs workspace filesystem with reflink support. The control plane can run separately; only the Runner needs access to these host facilities.
