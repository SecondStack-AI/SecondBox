# SecondBox v0.10.0

SecondBox v0.10.0 adds attributed command execution with Runner-owned egress
attribution. An application cannot safely attach credentials to ordinary Sandbox
traffic, because guest code can forge headers and background processes can outlive
individual commands. An attributed start gives one command and its descendants a
fresh exclusive Sandbox generation; the Runner binds that generation's outgoing
connections and sends bounded `SBXATTR1` evidence to a configured Unix gateway,
which authenticates its Runner peer before reading attribution. Applications retain
account authorization and credential custody.

These notes were written after publication from the release commit and
[#123](https://github.com/SecondStack-AI/SecondBox/pull/123).

## Behavior

- Firecracker and gVisor enforce the attributed route and refuse a second Exec, PTY,
  Port session, or file mutation in an attributed generation.
- Completion, cancellation, expiry, and Runner or control-plane connection loss
  retire the compute. A later command starts a new generation on the same durable
  Workspace.
- Microsandbox does not support attributed execution.

## Upgrade

The public API stays at version 1 and the Runner protocol window at `[4,4]`.
Attributed execution additionally requires the Runner's advertised
`attributed-execution` capability and a configured gateway `attributed_socket` on
the Runner host. Applying the release-owned standard resources appends an
attribution-enabled `agent-compartment` revision permitting two concurrent gateway
connections; existing Sandboxes keep their immutable older revision and do not gain
the permission. The `agent-compartment-isolated` Profile has no attributed
permission. The signed Firecracker bundle and trust anchor are unchanged from v0.6.0.

Guided Firecracker installations at v0.8.3 or newer update in place with the
v0.10.0 bootstrap after a verified PostgreSQL backup and with every Sandbox stopped.

```sh
npm install @secondstack-ai/secondbox@0.10.0
go get github.com/SecondStack-AI/SecondBox@v0.10.0
```
