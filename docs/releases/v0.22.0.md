# SecondBox v0.22.0

## Deployment boundary

Deployments from v0.14.0 onward update in place and retain their Sandboxes,
Workspaces, Profiles, and authorities. This release keeps public API v1 and the
Runner protocol window `[6,6]`. The signed execution bundle, trust anchor, and
standard Profile revisions are unchanged from v0.21.0.

Back up PostgreSQL before updating. Migrations `0035_live_sandbox_quota_index`
and `0036_sandbox_quota_ledger_on_increase` add the live-Sandbox quota index and
replace the Sandbox quota-ledger trigger. They are forward-only; rolling back
to v0.21.0 requires the pre-update database backup. The v0.15.0 migration
baseline is retained.

Update the control plane and all Runners to receive every cancellation fix.
Peers using v0.21.0 and v0.22.0 can connect in either update order; direct
cancellation confirmation needs both sides updated. When upgrading from an
earlier release, also follow the [v0.21.0 attribution migration and gateway
sequence](v0.21.0.md) and the intervening release notes.

## Concurrent Sandbox operations

On Firecracker and gVisor, each Exec, File, and Terminal operation now owns its
own negotiated guest stream. An open Terminal or long-running command no
longer holds up every other operation on the same Sandbox. Profile operation
limits and each operation's deadline still apply ([#197](https://github.com/SecondStack-AI/SecondBox/pull/197)).

## Cancellation and connection reliability

- Disconnecting a buffered Exec or File caller cancels its guest work instead
  of leaving it running until completion or its deadline ([#196](https://github.com/SecondStack-AI/SecondBox/pull/196)).
- The Runner confirms durable cancellation on its authenticated control
  connection. A disconnected operation releases its concurrent-operation slot
  once the Runner proves completion; later requests no longer remain stuck at
  `429 quota_exceeded` until the Sandbox stops. Attached direct Exec clients
  still receive their cancelled outcome ([#198](https://github.com/SecondStack-AI/SecondBox/pull/198)).
- Partial File uploads own cancellation before backend execution starts.
  Disconnect or cancellation releases the upload buffer and retains a terminal.
  Delivered cancellation commands replay after reconnect, and cancellation
  remains confirmable after the original terminal leaves the bounded cache.
  The Runner records fenced `operation_absent` evidence when no worker owns
  the operation; it does not fabricate unavailable request or Lease identifiers.
- A stalled direct Exec, File, or PTY peer cannot block control heartbeats.
  Each direct write has a five-second timeout, capped by its delivery deadline,
  so stalled delivery unwinds and cancellation can be confirmed.
- Refusing a Port Open to an approved guest port without a listener now ends
  that PortSession alone. It no longer drops the Runner's control connection
  and cancels unrelated work across its Sandboxes. Refused Exec and File Opens,
  and input or credit already in flight after a terminal, have the same
  operation-local behavior ([#194](https://github.com/SecondStack-AI/SecondBox/pull/194)).

## Sandbox start performance

Only admission and transitions that increase quota usage take the Tenant and
Subject quota-ledger locks. Placement locks the Sandbox's home Runner rather
than every Runner in its pool, and lifecycle effects run concurrently within
the configured batch bound. A starting Sandbox with an Instance waits for its
Assignment deadline or a Runner event instead of polling every 250 ms.

In the qualified single-host lifecycle benchmark, a burst of 32 starts improved
from 3.2 s to 1.8 s at p50 and from 4.4 s to 2.7 s at p95. The live-Sandbox
partial index also keeps quota reads from growing with retained deleted rows.
These are host-specific measurements; see the [benchmark evidence](../plans/evidence/2026-10-01-start-path-control-plane.md)
([#195](https://github.com/SecondStack-AI/SecondBox/pull/195)).

## Firecracker bundle and trust anchor

The release retains the signed `secondbox-0.17.0` Firecracker bundle and the
v0.12.0 RSA trust anchor. The public key's canonical DER SHA-256 remains:

```text
59c127f459b8c93ca422f2f6c5bd43ff1e17d50309a262b7aff1b07bf59a5ced
```

Standard Profile revisions and their spec digests remain unchanged from
v0.19.0. Use the released artifact manifest for exact bundle, image, and Profile
identities.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes
Linux amd64 OCI images. CLI and deployment binaries ship for Linux and macOS
on amd64 and arm64. It includes the Btrfs-image installer qualification; it
does not include gVisor pod qualification or an arm64 control-plane image.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.22.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.22.0`.
