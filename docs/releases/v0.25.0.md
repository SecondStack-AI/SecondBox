# SecondBox v0.25.0

## Deployment boundary

Deployments from v0.14.0 onward update in place and retain their Sandboxes,
Workspaces, Profiles, and authorities. There is no database migration, and
public API v1 is unchanged. The Runner protocol advances to generation 7
exactly: a generation 6 control plane rejects image preparation results that
carry no signature, so v0.24.0 and v0.25.0 peers refuse each other at connect.
Update the control plane and every Runner together.

Update in this order:

1. Delete the retired signing keys from `secondbox.toml`:
   `deployment.execution_image_public_key`,
   `deployment.execution_image_public_key_sha256`, and each Runner's
   `execution_image_public_key`, `execution_image_public_key_sha256`,
   `artifact_public_key`, and `artifact_public_key_sha256`. The strict decoder
   rejects them as unknown keys. Guided installs from earlier releases keep
   their recorded `secondbox.toml` until the update regenerates it, so the
   guided update, uninstall, and purge accept the keys that the installer
   wrote itself. Remove them from hand-written manifests.
2. Remove the `*_PUBLIC_KEY` and `*_PUBLIC_KEY_SHA256` variables from remote
   Runner and image-fetcher environments.
3. Stop the control plane and every Runner.
4. On each Runner host with snapshot-resume Profiles, materialize a new
   template from the v0.25.0 bundle into the template cache root before that
   Runner starts. The template key no longer carries a signing-key
   fingerprint, so a Runner ignores templates built by earlier releases. A
   Runner reads its cache when it connects, so one that starts without a new
   template does not advertise `snapshot-resume` until it is restarted after
   the template is in place, and Sandboxes of snapshot-resume Profiles cannot
   start on it.
5. Start v0.25.0 on the control plane and every Runner, and confirm that each
   snapshot-resume Runner advertises `snapshot-resume` before resuming service.

When upgrading from an earlier release, also follow the
[v0.24.0 notes](v0.24.0.md) and the intervening release notes.

## Signing removed

SecondBox no longer signs release microVM bundles or client-selected execution
images. Integrity rests on immutable digest pinning, the registry allowlist,
Tenant authorization, and the Runner's `SHA256SUMS`, manifest,
component-digest, and rootfs-contract checks.

- Bundles carry no `manifest.sig` or `signing.pub`. `verify.sh` and
  `just -f runner/Justfile verify-microvm-images` take only the artifact
  directory.
- The client execution-image builder and release staging take no signing or
  public key, and `secondbox-deploy init` no longer generates
  `secrets/execution-image.{pub,key}`.
- The control plane imports component identities from the manifest that the
  Runner returns for the digest-resolved image, instead of verifying a
  publisher signature. The Runner no longer advertises the `signed-artifacts`
  capability.
- Runner protocol generation 7 removes and reserves
  `PrepareImageResult.signature` (field 7).

## Release tooling

The release artifact manifest schema is
`secondbox.release/artifact-manifest/v7`. `microvm.bundleManifestDigest`
replaces `microvm.signedManifestDigest`, and `microvm.signingKeyFingerprint`
is gone. Recorded v5 and v6 manifests still decode, and the guided installer
still reads install plans that recorded a signing-key fingerprint.

## Firecracker bundles

The amd64 set ships the `secondbox-0.17.0` Firecracker bundle without its
`manifest.sig` and `signing.pub`. Its `manifest.json`, kernel, rootfs, and
component manifests are unchanged, so `microvm.bundleManifestDigest` names the
same bundle that earlier releases verified. The `microvm-artifacts` image digest
changes because the image no longer contains the signature files.

This is the first release that publishes an arm64 artifact set. Its bundle is
built for arm64 by the microVM image pipeline, and the arm64 Runner image and
standard `standard-arm64` bundles are under the `v0.25.0-arm64` tags.

Standard Profile revisions and their spec digests remain unchanged from
v0.19.0. Use the released artifact manifest for exact bundle, image, and Profile
identities.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes
Linux amd64 OCI images, and the arm64 artifact set publishes the
control-plane, Runner, installer-tools, and microVM-artifact images for Linux
arm64. CLI and deployment binaries ship for Linux and
macOS on amd64 and arm64. It includes the Btrfs-image installer qualification;
it does not include gVisor pod qualification.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.25.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.25.0`.
