# SecondBox v0.27.0

## Deployment boundary

Deployments from v0.14.0 onward update in place and retain their Sandboxes,
Workspaces, Profiles, and authorities. There is no database migration, the
Runner protocol stays at generation 7, and the Firecracker bundles, gVisor
materialization inputs, and standard Profile revisions are unchanged, so
v0.26.1 and v0.27.0 peers connect in either update order.

Public API v1 gains one platform operation. Clients built on earlier SDKs keep
working.

When upgrading from an earlier release, also follow the
[v0.26.1 notes](v0.26.1.md) and the intervening release notes.

## Switching a RunnerPool between compute backends

A RunnerPool is still sealed to the compute backend of the first Runner that
registers in it. The new platform operation
`POST /v1/runner-pools/{runnerPoolName}:unseal-backend` clears that seal so an
installation can move its Runners between Firecracker and gVisor without
discarding Sandboxes. Both backends serve the same raw ext4 Workspace images,
so a Runner that re-registers under the same `runner_id` on the other backend
keeps every Workspace it homes.

- The operation takes the pool's revision in `If-Match`, like
  `updateRunnerPool`. It refuses with 409 `runner_pool_backend_in_use` while any
  Runner of the pool is not offline or holds an active connection, while any of
  its assignments is live, or while a fence exhausted its retries without
  termination evidence, so it never strands compute on the old backend.
- The next registration seals the pool again, to the backend of the
  registering Runner.
- Each unseal is audited as `runner_pool.backend_unsealed`.
- The backend kind stays out of every public schema.
- The CLI alias is `secondbox runner-pools unseal-backend`, and the Go and
  TypeScript SDKs gain the matching method.

Every Sandbox of the pool changes isolation class with its Runner, and a
Sandbox of a `snapshot_resume` Profile cannot start on gVisor. See the gVisor
runtime guide's "Switching an installation between Firecracker and gVisor".

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes
Linux amd64 OCI images, and the arm64 artifact set publishes the
control-plane, Runner, installer-tools, and microVM-artifact images for Linux
arm64. CLI and deployment binaries ship for Linux and macOS on amd64 and
arm64. It includes the Btrfs-image installer qualification; it does not
include gVisor pod qualification.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.27.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.27.0`.
