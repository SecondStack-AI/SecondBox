# SecondBox v0.2.3

SecondBox v0.2.3 is a patch release that repairs the colliding migration prefix which stopped v0.2.0 and v0.2.1 deployments from starting on v0.2.2, and restores TypeScript SDK terminal replay parity.

## Upgrade path

**Upgrade directly from v0.2.0 or v0.2.1 to v0.2.3 and skip v0.2.2.** A deployment already running v0.2.2 is repaired automatically on its first start on v0.2.3; no operator action is required and no migration is re-executed.

## The failure mode

v0.2.0 shipped `0010_lifecycle_hot_path_indexes`. v0.2.2 added the lifecycle fence command-kind retag as `0010_lifecycle_fence_command_kind`, which sorts before it. The two orderings are irreconcilable: a database upgraded through v0.2.0 or v0.2.1 recorded `0010_lifecycle_hot_path_indexes` at ledger position 9, while a fresh v0.2.2 install recorded the fence migration there instead. Because migrations run before the control plane opens its listeners and the ledger must be an exact positional prefix of the embedded lineage, an upgrade from v0.2.0 or v0.2.1 to v0.2.2 failed validation and the control plane refused to start — permanently, on every restart.

## The fix

The fence migration is renamed to `0013_lifecycle_fence_command_kind` with byte-identical content, so a recorded checksum keeps matching, and it now orders last in the lineage as every release other than v0.2.2 already did.

A checksum-verified ledger repair runs before prefix validation and handles every published ledger shape:

- a v0.2.0 or v0.2.1 ledger upgrades cleanly, applying the fence migration last;
- a v0.2.2 ledger, which recorded the colliding name, has that row renamed in place inside one transaction, preserving `applied_at`; nothing is re-executed;
- a crash-window ledger that recorded the fence row without the migrations preceding it in the embedded lineage is refused with an explicit instruction to run the recording release to completion first;
- a row carrying the fence name with any other checksum is refused rather than renamed.

Every 4-digit numeric prefix must now be unique across the embedded lineage, so a colliding prefix cannot embed again.

## SDK and qualification fixes

The TypeScript SDK gains `connectTerminalAfter`, matching the Go SDK: it threads the replay cursor through the connector descriptor, sends the `SecondBox-Terminal-After-Sequence` header, resumes output sequencing at `afterSequence + 1`, and surfaces a rejected WebSocket handshake — including `terminal_replay_evicted` — as the same typed Problem error Go returns. The SDK parity contract test asserts the capability in both SDKs.

`SecondBox.request` no longer discards the HTTP status when an error body is not a Problem document; it surfaces the transport error carrying the status and a bounded body instead of a `SyntaxError`.

`scripts/test-firecracker.sh` exports `SECONDBOX_RUNNER_QUALIFY_FIRECRACKER=1`, so an unqualified machine fails loudly instead of skipping every targeted test and passing vacuously. Six runner configuration errors now name environment variables that actually exist — `SECONDBOX_RUNNER_ARTIFACT_PUBLIC_KEY`, `SECONDBOX_RUNNER_ARTIFACT_PUBLIC_KEY_SHA256`, and `SECONDBOX_RUNNER_FIRECRACKER_SHARED_IMAGE_PATH`.

## Install

Download `secondbox` and `secondbox-deploy` for your OS and architecture from the assets below. For Linux amd64:

```sh
mkdir -p ~/.local/bin
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.3/secondbox_0.2.3_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.3/secondbox-deploy_0.2.3_linux_amd64
install -m 0755 secondbox_0.2.3_linux_amd64 ~/.local/bin/secondbox
install -m 0755 secondbox-deploy_0.2.3_linux_amd64 ~/.local/bin/secondbox-deploy
```

Install an SDK at the same version:

```sh
npm install @secondstack-ai/secondbox@0.2.3
go get github.com/SecondStack-AI/SecondBox@v0.2.3
```

## Runtime requirements

Executing Sandboxes requires a Linux amd64 Runner host with KVM and TUN, cgroup v2, and a dedicated XFS or Btrfs workspace filesystem with reflink support. The control plane can run separately; only the Runner needs access to these host facilities.
