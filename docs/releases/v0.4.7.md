# SecondBox v0.4.7

SecondBox v0.4.7 makes guided single-host installation independent of Docker's finite automatic address pools.

## Fixed

- Preflight now records existing Docker IPAM allocations alongside host routes. The installer deterministically chooses separate RFC1918 `/24` networks for Firecracker guests and the Compose backend, rejects every overlap, and includes both values in the final review.
- The accepted Compose backend CIDR is carried into the generated deployment manifest and an embedded Compose IPAM overlay. Docker therefore creates the installation's project network from the reviewed subnet instead of attempting to allocate from an exhausted daemon-wide default pool.

This corrects guided installations from v0.4.4 through v0.4.6 that reached `Compose startup` and failed with `all predefined address pools have been fully subnetted` on Docker-heavy hosts. A failed receipt-compatible operation can be recovered without re-downloading verified assets by following the [pre-v0.4.7 network recovery procedure](../operations/guided-single-host-install.md#recover-a-pre-v047-compose-network-failure); it covers collision review, exact Compose identity and labels, verification, resume, empty-network rollback, and v0.4.7-bootstrap exact-project teardown with a journaled pre-Compose retry after startup or a later installer-stage failure. New v0.4.7 operations allocate the reviewed network automatically.

No database, public API, Runner protocol, guest, Profile, or microVM-bundle change is involved.

## Download and install

```sh
curl -fsSL https://github.com/SecondStack-AI/SecondBox/releases/latest/download/install.sh | sh
```

Standalone binaries and SDKs use version `0.4.7` and tag `v0.4.7`.
