# SecondBox v0.32.3 — withdrawn before publication

Withdrawn before publication: live AWS qualification found that the AMI builder
could not observe its sealing proof after EC2 shutdown. No v0.32.3 release assets
were published. The tag remains immutable; use the next qualified patch.

## Deployment boundary

This release adds the optional pre-baked AWS worker AMI workflow. Public API v1,
Runner protocol generation 8, database migrations and standard Profile revisions
are unchanged from v0.32.2. Existing v0.32.1/v0.32.2 deployments update in place;
the fleet controller and enrollment tools must use the same build as the control
plane. No existing fleet is switched to an AMI automatically.

The worker bundle command now requires the checksum-verified Linux amd64
enrollment binary from the selected release between the enrollment CA and output
directory arguments. Use the updated invocation in the
[AWS fleet reference](../../deploy/aws-fleet/README.md); the builder no longer
compiles an enrollment client with a development identity.

Upgrades from v0.31.x or earlier must follow the complete
[v0.32.1 coordinated cutover procedure](v0.32.1.md#deployment-boundary).
It requires cloud/volume and archive object cleanup to settle before recovery
capture, and enrollment plus a start on each served Profile to succeed before
reopening service and resuming policies.

## AWS worker bundle credentials and cache integrity

The v0.32.1/v0.32.2 bundle builder copied the whole optional Runner execution
cache, including transient registry authentication files left during image
preparation or after an interrupted process. The builder now exports only the
fixed execution-bundle files from complete digest directories and verifies
their checksums, excluding authentication, operation and retention records.

Operators who packaged a mutable Runner cache should inspect their existing
bundle contents and revoke any registry credentials included there before
continuing to distribute that bundle. Rebuild from a quiesced cache or offline
copy with the updated builder.

Worker bootstrap verifies private staging before atomically publishing a
complete digest directory under the Runner lock. Interrupted staging can be
retried without retaining partial published image bytes or replacing live cache
locks.

## Pre-baked worker AMIs

The reference builds an identity-free AMI from an explicitly pinned worker
bundle. Runtime images are preloaded; execution-image data stays compressed
until it is staged sparsely onto each worker's fresh XFS disk. Every worker
enrolls independently and receives its own credentials. AMIs contain no enrolled
worker identity or workspace data.

AMI construction requires a single EBS root at `/dev/sda1`, checks it again
before imaging, and requires a fresh nonce acknowledgement after identity
scrubbing. An unrelated instance stop is insufficient. Catchable SIGTERM uses
the bounded, receipted cleanup path, including when it first arrives during
cleanup. After SIGKILL or host loss, inspect the receipt and owned AWS inventory
before retrying.

Select pre-baked mode explicitly and keep the AMI, bundle location and both SHA
inputs consistent. An absent or mismatched cache fails explicitly. Pre-baking
has not demonstrated a cold-start latency improvement; initialization of cold
EBS snapshot blocks remains a workload-specific consideration. The preceding
helper revision passed a real Code build/archive/zero-worker/restore scenario;
the new console acknowledgement and build-boundary guards have local regression
coverage and still require live AWS qualification for the selected deployment.

See [AWS workers](../../deploy/aws-fleet/README.md) for bundle construction,
provisioner/controller permissions, cache requirements and safe retirement.

## Distribution and bundle identity

The existing amd64 and arm64 release matrix is retained. The AWS gVisor worker
reference remains Linux amd64. CLI, deploy, fleet-controller and fleet-enrollment
binaries ship for Linux/macOS on amd64/arm64; fleet tools are installed separately
by their operator.

The planned Firecracker bundles were those documented by v0.32.2/v0.31.0.
No v0.32.3 artifact manifests, checksums or container images were published.
Do not deploy this tag. The planned SDK coordinates were
`@secondstack-ai/secondbox@0.32.3` and
`github.com/SecondStack-AI/SecondBox@v0.32.3`.
