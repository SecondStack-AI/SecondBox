# SecondBox v0.5.2

SecondBox v0.5.2 fixes large File API writes that exceeded gRPC's default 4 MiB receive limit between the Runner and guest. A 52,929,536-byte file now transfers successfully through the same bounded protocol used by smaller files, and a file-operation failure no longer leaves later file and Exec operations unusable.

This is a compatible patch release for v0.5.0 and v0.5.1. The public HTTP contract, Runner protocol schema, guest protocol schema, database schema, deployment manifest, standard resources, and signed microVM bundle are unchanged.

## Large writes remain bounded

The Runner previously placed the complete write payload in one guest-protocol `FileChunk`. The guest gRPC server retains its default 4 MiB message limit, so a valid file above that size terminated the protocol stream even when the Runner's configured file-transfer limit allowed it.

Writes now use sequential 64 KiB frames with monotonically increasing byte offsets and protocol sequence numbers. Each frame references its portion of the caller's payload without cloning the complete file. Empty files and existing small writes retain their behavior, while declared-size, checksum, cancellation, and transfer-limit validation remain enforced.

The regression coverage runs through the real Runner-to-guest gRPC and Firecracker-vsock adapter. It covers the chunk-size boundaries, the 52,929,536-byte reproduction, checksum and declared-size failures, and successful file and Exec operations after a failed file operation.

## Upgrade

Upgrade the Runner image on deployments that accept files larger than 4 MiB. Existing v0.5.0 and v0.5.1 control planes, SDK clients, and signed guest bundles remain compatible, but coordinated deployments should use the v0.5.2 release assets.

```sh
curl -fsSL https://github.com/SecondStack-AI/SecondBox/releases/latest/download/install.sh | sh
npm install @secondstack-ai/secondbox@0.5.2
go get github.com/SecondStack-AI/SecondBox@v0.5.2
```
