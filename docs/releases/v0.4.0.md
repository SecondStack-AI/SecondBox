# SecondBox v0.4.0

SecondBox v0.4.0 adds a qualified guided installer for one loopback-only Linux amd64 deployment and gives both CLIs a consistent terminal presentation and help system. The installer verifies one immutable public release, records every accepted host and authority decision, survives interruption, and proves the finished deployment by running a command inside a Firecracker microVM.

## Compatibility and upgrade

Existing v0.3.1 deployments need no database migration, public API change, Runner protocol change, or guest update. The control plane and Runner remain wire-compatible with v0.3.1, and the v0.3.0 microVM bundle and trust anchor carry forward unchanged. No Profile is re-pinned merely by upgrading the binaries.

Applying the release-owned standard resources does create a new `agent-compartment` Profile revision. Its maximum command deadline is now 900 seconds instead of 120 seconds, matching that Sandbox's maximum lifetime. Callers may request enough time for an install, build, or large search without the Profile rejecting the deadline; the Sandbox lifetime remains the outer bound.

The release artifact manifest advances to `secondbox.release/artifact-manifest/v5` because it now binds the installer-tools image, bundled PostgreSQL and object-store images, host binary digests, the bootstrap script, and clean-VM installer qualification evidence. Use the v0.4.0 `secondbox-deploy` binary or its `install.sh`; older deployment binaries deliberately reject the new release contract instead of partially interpreting it.

## Guided single-host install

The guided path installs a development-mode control plane, PostgreSQL, object storage, and one same-host Firecracker Runner. It is deliberately Linux amd64, systemd, cgroup v2, Docker Compose v2, KVM, TUN, and loopback-only. It does not create production authority, configure remote Runners, select another compute backend, or enable automatic updates.

Run the read-only host check first:

```sh
secondbox-deploy install --check
```

The check performs no sudo, download, image pull, directory creation, mount, or service change. It reports every relevant device, filesystem, capacity, port, UID range, software, DNS, and release-connectivity finding in one pass.

Start the published wizard with:

```sh
curl -fsSL https://github.com/SecondStack-AI/SecondBox/releases/latest/download/install.sh | sh
```

The bootstrap embeds the release version and the Linux amd64 deployment-binary digest. It downloads and verifies only that binary; the installer performs release verification and displays its complete privileged action list before requesting sudo.

The wizard reviews an existing dedicated XFS/Btrfs mount or a fully allocated Btrfs filesystem image, the conservative resource budget, generated authority categories, capacity, network settings, retention, release identity, expected downloads, and uninstall behavior. The accepted protected plan records every exact path and all seven digest-pinned images before creating any secret or host resource.

After host preparation, it materializes the verified deployment artifacts, generates the explicit deployment manifest and authorities, enrolls the Runner, starts Compose, logs in the CLI, waits for cold-boot capacity, and runs:

```sh
secondbox run durable-coding -- python3 -c 'print("hello from a microVM")'
```

See [guided single-host installation](../operations/guided-single-host-install.md) for resource requirements, every privileged action, recovery, support collection, uninstall, and purge semantics.

## Recovery and removal

Each durable installer stage is recorded. An interrupted installation resumes against the exact plan, host identity, file digests, image identities, Compose project, CLI configuration, and receipt:

```sh
secondbox-deploy install --resume /absolute/path/to/operation
```

Ordinary uninstall stops the deployment while preserving its database, object store, Workspace, artifacts, manifest, identities, binaries, CLI configuration, and receipt. Permanent deletion is a separate typed-confirmation workflow:

```sh
secondbox-deploy uninstall /absolute/path/to/operation
secondbox-deploy uninstall --purge /absolute/path/to/operation
```

A create-only, mode-`0600` installer support archive is bounded and rejects exact secret values, secret-bearing markers, Workspace content, database rows, object-store objects, the plan, and process environments.

## CLI presentation

Both CLIs now accept global presentation flags before the command:

```sh
secondbox --output plain --color never sandboxes list
secondbox --output json sandboxes list | jq '.items[] | .id'
secondbox --accessible login
```

Interactive terminals receive compact summaries, width-aware tables, lifecycle status on stderr, and theme-aware color. Pipes retain the established machine bytes. `NO_COLOR` disables automatic color, `TERM=dumb` and CI disable automatic styling, and `--accessible` or `SECONDBOX_ACCESSIBLE=1` selects line-oriented prompts.

No arguments, `help`, `--help`, and `-h` now print root help with exit status zero. Raw files, artifacts, logs, guest streams, generic operation responses, and Docker Compose output are never styled or decoded. See the [CLI output contract](../operations/cli-output-contract.md) before using a command in automation.

## Download and install

Download standalone binaries from the release:

```sh
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.4.0/secondbox_0.4.0_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.4.0/secondbox-deploy_0.4.0_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.4.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
chmod +x secondbox_0.4.0_linux_amd64 secondbox-deploy_0.4.0_linux_amd64
```

Install an SDK at the same version:

```sh
npm install @secondstack-ai/secondbox@0.4.0
go get github.com/SecondStack-AI/SecondBox@v0.4.0
```

The release also includes Linux and macOS CLI binaries for amd64 and arm64, the OpenAPI document, standard resource bundles, installer bootstrap and qualification evidence, KVM scenario evidence, checksums, SBOM, source archive, and digest-addressed control-plane, Runner, installer-tools, and microVM-artifact images.
