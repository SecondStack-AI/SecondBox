# SecondBox v0.13.0

SecondBox v0.13.0 adds configurable limits and retained Workspace storage
observations. It was published without release notes; these were written after
publication from the release commit and
[#141](https://github.com/SecondStack-AI/SecondBox/pull/141).

## Configurable limits

Policy ceilings and quota dimensions are explicit integer-or-null values with
complete-object validation and nullable admission headroom. Effective lifecycle
policy is pinned at Sandbox creation. Subjects may delegate lifecycle selection for
future Sandboxes; fresh Agent Profiles use 60-second idle shutdown and unlimited
maximum runtime, while finite workloads keep age-based termination, command
deadlines, cancellation, ownership fences, and physical Runner admission. Tenant
quotas can be raised on existing Tenants without recreating retained resources, and
applications read their effective policy and quota headroom.

## Workspace storage observations

Sandbox reads expose timestamped Workspace allocated-block usage and
admission-pressure freshness without renewing activity, changing compute state,
or exposing host identities.

## Deployment boundary

Schema changes require a clean initialization. Existing deployments and their
Workspaces remain separate; there is no state adoption or history rewrite. The
signed `secondbox-0.12.0` Firecracker bundle and trust anchor are unchanged.

The tag was cut at `1645f10` on the branch of #141 before that branch was rebased
onto `main`. `git log v0.13.0..main` therefore lists re-landed commits under
different hashes; the tagged tree is identical to `main`'s `24ac255`. The later
unlimited Snapshot retention fix is not in v0.13.0; it ships in v0.14.0, which
requires a fresh database.

```sh
npm install @secondstack-ai/secondbox@0.13.0
go get github.com/SecondStack-AI/SecondBox@v0.13.0
```
