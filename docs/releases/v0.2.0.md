# SecondBox v0.2.0

SecondBox v0.2.0 hardens microVM and data-plane isolation, removes fleet-wide locking from placement and lifecycle hot paths, brings the TypeScript SDK to exact parity with Go, and binds release staging to scenario qualification evidence.

## Highlights

- Stopped Sandboxes no longer count against subject CPU and memory quotas, so long-lived projects with accumulated stopped Sandboxes can keep creating new ones instead of hitting `quota_exceeded`.
- Every jailed Firecracker instance runs under a unique UID from a validated manifest range with crash-safe lease reconciliation, and host-side cgroups cap cpu and pids alongside memory.
- Sandbox creation, Snapshot-clone, and relocation placement rank candidates without a fleet-wide Runner lock, and lifecycle workers no longer block each other on claim scans and Lease sweeps.
- Terminal sessions checkpoint durable accounting instead of writing PostgreSQL per keystroke, and reattachment adopts the Runner's authoritative input sequence.
- The TypeScript SDK matches Go exactly: bounded `readFile` streaming, the full argv/shell `exec`/`run` command union with standard input, and a required Flue adapter `maximumFileBytes`.
- `secondbox-deploy runner-template` scaffolds a complete, commented `[[runners]]` declaration whose placeholders cannot accidentally validate.
- Release artifacts embed qualification evidence from a full KVM scenario-suite pass at the exact staged commit.

## Breaking changes

- The proxied Port transport wire value is now `proxied` instead of `relay` across the OpenAPI contract, SDKs, and stored session rows. Update any consumer that matches on the old value.
- The TypeScript SDK `readFile` requires an explicit maximum-bytes bound, and the Flue adapter configuration requires `maximumFileBytes`.
- Reattaching a running terminal session through a Runner that predates the input-sequence protocol field is refused with the typed replay-evicted result.

## Install

Download `secondbox` and `secondbox-deploy` for your OS and architecture from the assets below. For Linux amd64:

```sh
mkdir -p ~/.local/bin
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.0/secondbox_0.2.0_linux_amd64
curl -fLO https://github.com/SecondStack-AI/SecondBox/releases/download/v0.2.0/secondbox-deploy_0.2.0_linux_amd64
install -m 0755 secondbox_0.2.0_linux_amd64 ~/.local/bin/secondbox
install -m 0755 secondbox-deploy_0.2.0_linux_amd64 ~/.local/bin/secondbox-deploy
```

Install an SDK at the same version:

```sh
npm install @secondstack-ai/secondbox@0.2.0
go get github.com/SecondStack-AI/SecondBox@v0.2.0
```

## Fixes included in this release

- Subject quota usage sums only active Sandbox states, and cleanly fenced assignments with stop authority release in the fencing transaction instead of parking unclaimably after the generation advances.
- The in-memory data-plane broker drops and counts frames for closed or unknown session routes instead of tearing down the Runner control connection, and a slow consumer no longer blocks the control-stream reader.
- Audit events record the resolved tenant and subject attribution in the service layer for operator and subject actions.
- Expired idempotency records are never replayed and are swept periodically, and per-stream Runner-connection dedupe state is released at stream termination.

## Runtime requirements

Executing Sandboxes requires a Linux amd64 Runner host with KVM and TUN, cgroup v2, and a dedicated XFS or Btrfs workspace filesystem with reflink support. The control plane can run separately; only the Runner needs access to these host facilities.
