# SecondBox v0.12.0

v0.12.0 rotates the Firecracker microVM bundle and its signing authority. The
`secondbox-0.12.0` bundle is built from source commit
`fc635558f1cdb66704787aacc2704cf9ee8d4b81`, replacing the bundle built on
2026-08-07. Updating the Runner binary alone does not update the guest agent
inside the signed rootfs.

## Operator action: reinstall existing deployments

Existing deployments must be reinstalled and their resources recreated for
this release. The guided updater refuses runtime or toolchain bundle digest
changes because existing Sandboxes remain pinned to immutable Profile
revisions. Do not bypass that refusal or overwrite a populated artifact
directory with the new bundle.

Quiesce applications and retain a coordinated backup for complete rollback.
Retire the old Sandboxes, reinstall using the release's verified artifacts and
trust anchor, and recreate resources against the new signed asset catalog and
Profile revisions. Coordinate the bundle installation, catalog, and standard
resources; a Runner rejects assignments pinned to different component digests.
An old verified bundle retains its old guest behavior and does not provide the
fixes below.

## New trust anchor and bundle identity

The previous private signing key was lost. This bundle uses a new RSA-4096 key;
the release carrying it must pin this canonical public-key DER SHA-256:

```text
59c127f459b8c93ca422f2f6c5bd43ff1e17d50309a262b7aff1b07bf59a5ced
```

Provision the public key independently and verify it against the release-bound
fingerprint. Never use the bundle's own `signing.pub` as the independent trust
anchor. The private key is operator-held and is not distributed.

The bundle retains the 6.12.94 kernel with SHA-256
`7c48460080dd76ea685570c50f6c80028c31b48f8b14ee9afde6605933b83f14`,
a 10240 MiB ext4 rootfs, a 1024 MiB ext4 shared image, and `/init` as its
entrypoint. The kernel binary was reused; the builder accepts an explicitly
empty optional kernel config and records supplied-kernel provenance.

## Guest fixes now shipped in Firecracker

- [#127](https://github.com/SecondStack-AI/SecondBox/pull/127) returns unused
  port byte credit after short socket reads, preventing forwarding stalls.
- [#128](https://github.com/SecondStack-AI/SecondBox/pull/128) validates guest
  socket read counts against reserved credit, alongside bounded Runner adapter
  credit and read sizes.
- [#134](https://github.com/SecondStack-AI/SecondBox/pull/134) drains trailing
  streaming input without blocking the guest connection, preserves command
  exit status when a process stops reading stdin, and keeps completion credit
  flowing after cancellation. The accompanying Runner, control-plane, and SDK
  changes allow deadline outcomes to reach streaming clients.

See the [microVM image pipeline](../operations/microvm-image-pipeline.md) and
[release operator setup](../operations/release-operator-setup.md) for independent
signature verification and coordinated installation.
