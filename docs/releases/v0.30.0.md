# SecondBox v0.30.0

## Deployment boundary

Deployments from v0.14.0 onward update in place and retain their Sandboxes,
Workspaces, Profiles, and authorities. There is no database migration. Public
API v1, Runner protocol generation 7, the Firecracker bundles, gVisor
materialization inputs, and standard Profile revisions are unchanged, so
v0.29.0 and v0.30.0 peers connect in either update order.

Update every control-plane process to expose the new health response.
v0.29.0 Runners need no update for this feature. When upgrading from an
earlier release, also follow the [v0.29.0 notes](v0.29.0.md) and the
intervening release notes, including their trust-store requirements.

## Control-plane release identity

`GET /healthz` now returns the answering control-plane process's release
`version` and `sourceCommit` alongside `status`:

```json
{"status":"healthy","version":"0.30.0","sourceCommit":"<release commit>"}
```

A client of an independently operated SecondBox server can use `version`
to check that the server supports a feature before sending a request that
uses it, such as `capacityWaitMilliseconds`, introduced in v0.28.0.
Previously, the API protocol string and the client's own release were the
only signals, and an older server rejected a newer request member only
when the client sent it. Treat a missing version from an older server as
unknown support; do not infer the server's release from the SDK version.

The response identifies only the answering control-plane process. It does
not describe connected Runners, database readiness, or backend capabilities.
During a rolling update, different control-plane processes may report
different releases. See [Server feature checks](../operations/downstream-release-integration.md#server-feature-checks).

## Bundle identity

The amd64 `secondbox-0.17.0` Firecracker bundle and the arm64 bundle are
unchanged from v0.29.0, including their guest agents and trust stores.
This release does not replace the Firecracker default guest trust store
described in the [v0.29.0 notes](v0.29.0.md#emudhra-intermediate-ca-compromise).
Take the bundle and gVisor materialization digests from the verified artifact
manifest for the selected architecture.

## Distribution

The default lean release qualifies Firecracker and local gVisor and publishes
Linux amd64 OCI images, and the arm64 artifact set publishes the
control-plane, Runner, installer-tools, and microVM-artifact images for Linux
arm64. CLI and deployment binaries ship for Linux and macOS on amd64 and
arm64. It includes the Btrfs-image installer qualification; it does not
include gVisor pod qualification.

Install the TypeScript SDK with `npm install @secondstack-ai/secondbox@0.30.0`.
The Go module is `github.com/SecondStack-AI/SecondBox@v0.30.0`.
